Life of a ticket

#What happensParts involved
1A shopper hits the expiry bug; Figma Merch Store files a ticketPylon
2Pylon sends a signed webhook, or the /simulator page sends the same payloadFastAPI POST /webhooks/pylon, HMAC check
3FastAPI stores the ticket and enqueues a jobProcrastinate on the agent Postgres
4A Procrastinate task starts the ticket's LangGraph run (thread ID = ticket ID, checkpointed in Postgres); the context node fetches tenant, recent deploys, flag changes and incidentsLangGraph · tenants, deploys, flag_changes
5Enrichment: one LLM call returns identifiers, time window, symptom and likely services; code checks every IDPydantic AI → LLM provider
6Retrieval and Jev run side by side: hybrid search over help sections and past or open tickets; Jev returns type, service, severity and revenue-blockingLocal embeddings + pgvector · TypeSafe Jev API
7A conditional edge sends how-to tickets to Layer 1 and requests to request triage (single LLM calls). Tech issues go to the duplicate check, then the brief nodeLangGraph routing, Pydantic AI
8The brief node fans out to both analyst nodes, which run as parallel branches. HolmesGPT queries Prometheus, Jaeger, OpenSearch, astronomy-db and the history toolset. mini-swe-agent runs read-only commands in the codebox against the deployed worktree and the code indexHolmesGPT · mini-swe-agent · sandbox observability · codebox
9Their answers become Findings, with evidence checked against their tool logs. The handoff node then decides in code whether one analyst needs the other: production's exact error goes to the codebase analyst, an analyst's own question goes to the other, and a regression the code found goes to the data analyst to confirm. A short follow-up run answers each question (at most three), and its findings come back for the next one. The verdict call then decides false positive, bug, config incident or inconclusive, and rules in code check itLangGraph loop · HolmesGPT · mini-swe-agent · Pydantic AI → LLM provider
10Layer 3 creates the Linear issue for the owning team. When a person must approve the reply, the graph pauses with interrupt(); the Approve button resumes it from its checkpoint and the reply goes back through PylonLinear API · console · Pylon
11The ticket is written to ticket memory as open, so a differently worded repeat can find itretrieval_docs, investigations
12The worker streams the graph (node updates, plus tool calls, commands and model text from inside nodes) into the events table. Postgres NOTIFY wakes the SSE stream, and the console's pipeline and inspector update live; the admin approves replies thereevents → FastAPI SSE → TanStack Query → React Flow UI + AI Elements
13Every model call and analyst run is a span sent to the shop's Collector, so the agent's trace sits in Jaeger next to the shop'sPydantic AI OTel → Collector → Jaeger

Cflag.sh paymentFailure 25% edits demo.flagd.json, which flagd reloads, and records the changeflagd · flag_changes
DScenario scripts place orders through the frontend proxy, before and after a deploy; the load generator keeps background traffic flowingfrontend-proxy → services → Collector

Every connection from the agent into the sandbox and the codebases is read-only. The only writes are to the agent's own Postgres, Linear, and replies to Pylon.
